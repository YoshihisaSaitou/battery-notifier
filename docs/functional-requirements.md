# 機能要件仕様書

文書ID: FRS-001  
版: 0.6
状態: Draft  
最終更新: 2026-08-11

## 1. 前提

- v1.0の監視対象はMobile端末の電池である。
- 電池残量は`0..100`の整数百分率へ正規化する。
- 初期しきい値は20%、設定可能範囲は5%から100%、刻みは1%とする。
- 通知は単なる「現在値が以下」ではなく「しきい値を上から下へ跨いだイベント」で発生させる。

#### 2.1.1 Wearからのしきい値変更状態

- 正常なMobile stateを一度も受信していない場合と、Mobile側の対応Capabilityを確認できない場合は保存操作を無効にし、Mobileの起動・更新・接続確認を案内する。
- Fresh、Delayed、Staleのいずれでも下書き編集は許可する。Stale値から送信した要求はMobileの現在値との比較で適用または`CONFLICT`になる。
- 1件の要求が未確定の間は別の要求を開始しない。ユーザーは同じ`requestId`を明示的に再試行できる。
- Mobileが要求を適用した後に結果応答だけが失われた場合、同じ`requestId`の再試行へ保存済み結果を返し、設定変更を重複適用しない。
- `CONFLICT`または入力拒否ではMobileの有効なしきい値を表示し、ユーザーがその値を基準に新しい要求を作る。
- Wearプロセス・端末再起動後も下書き、`requestId`、送信状態をProto DataStoreから復元する。未確定要求を再起動だけで自動送信しない。

### 2.2 電池監視と判定

| ID | 要件 |
|---|---|
| FR-010 | 監視中は`ACTION_BATTERY_CHANGED`をコンテキスト登録したReceiverで受信する |
| FR-011 | `level`と`scale`から`floor(level * 100 / scale)`を算出し、0～100に制限する |
| FR-012 | しきい値が5～99%の場合は`previousLevel > threshold && currentLevel <= threshold`、100%の場合は`previousLevel == 100 && currentLevel < 100`で到達イベントを生成する。いずれも監視中・armed・非充電時に限る |
| FR-013 | 初回観測時にすでにしきい値以下でも、監視開始の直後に1回だけ状態通知するかを設定で制御する。v1.0既定値は通知しない |
| FR-014 | 同一放電サイクルでは同じしきい値イベントを1回だけ通知する |
| FR-015 | 残量が`min(100, threshold + 2)`以上へ戻ると再アームする。threshold=100では100%到達で再アームする。充電開始後も同じ再アーム値を満たした場合だけ再アームする |
| FR-019 | threshold=100の初回観測が100%なら通知せずarmedとして開始し、次の100→99以下で1件生成する。初回観測が99%以下なら通知せずdisarmする。設定変更だけではイベントを生成しない |
| FR-016 | 充電中も状態同期は継続するが、新しい低残量通知は生成しない |
| FR-017 | 監視停止中はしきい値イベントを生成せず、Wearには監視停止状態を同期する |
| FR-018 | 端末時刻変更に影響されない順序判定用に単調増加`sequence`を使用する |

### 2.7 同期と復旧

| ID | 要件 |
|---|---|
| FR-060 | Mobileは固定DataItemパスへ最新状態を書き込む |
| FR-061 | 状態更新には`schemaVersion`、`sequence`、取得時刻を含める |
| FR-062 | Wearは順序キーが保存済み以下の状態を破棄する |
| FR-063 | 切断中もMobileは最新DataItemを更新し、再接続後に最新状態へ収束させる |
| FR-064 | 接続・再接続時にMobileは現在値を再取得してurgent送信する |
| FR-065 | schemaVersion、不正型、範囲外、必須項目欠落を検証し、異常データを保存・表示・通知に使用しない |
| FR-066 | 互換性のない新しいschemaVersionを受信した場合は診断状態へ記録し、クラッシュしない |
| FR-067 | Mobileでユーザーが「今すぐ同期」を実行した場合、同期開始から結果確定までボタンを無効化して進捗表示と「同期中」の操作文言・状態文言を表示する。高速完了時も同期中表示を500ms以上保持し、Idleの「今すぐ同期」「同期できます。」を同期処理中に表示しない |
| FR-068 | Mobileの「今すぐ同期」の付近に、電池状態は通常自動でWearへ同期されることと、この操作は自動同期されない場合または最新状態へ手動更新したい場合に使用することを日英で常時表示する |
