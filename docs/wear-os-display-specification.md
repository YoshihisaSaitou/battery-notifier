# Wear OS表示仕様書

文書ID: WDS-001  
版: 0.3
状態: Draft  
最終更新: 2026-08-11

## 1. 表示面

| 表示面 | 目的 | 更新契機 |
|---|---|---|
| Wearメイン画面 | 詳細な状態確認と再試行 | 画面表示、DataItem受信、1分ごとの鮮度再評価 |
| Tile | 素早い確認とアプリ起動 | Tile要求、DataItem受信後の更新要求 |
| コンプリケーション | ウォッチフェイス常時確認 | システム要求、DataItem受信後の更新要求 |
| Wear通知 | しきい値到達を知らせる | 有効なThresholdReachedEvent受信 |
| Wear通知 | スマートフォンの満充電を知らせる | 有効なFullChargeReachedEvent受信 |

## 2. Wearメイン画面

### 情報優先順位

1. Mobile電池残量（最大の文字）。
2. 充電中/放電中。
3. 同期鮮度と最終更新時刻。
4. 設定しきい値と監視状態。
5. 同期再試行または、対応Mobileが到達可能な場合のしきい値編集操作。
6. 満充電通知のMobile確定済みON/OFFと変更状態。

### 状態別表示

| 状態 | 条件 | 表示 |
|---|---|---|
| Fresh | 受信から0～2分 | `68%`、充電アイコン、`たった今更新 / Updated just now` |
| Delayed | 2分超～5分 | `68%`、`3分前 / 3 min ago`、控えめな注意アイコン |
| Stale | 5分超 | `68%`を維持し、`古いデータ / Data may be outdated`、最終更新時刻、再試行 |
| No data | 正常値未受信 | `--%`、Mobileとの接続・インストール案内 |
| Monitoring off | Mobileから無効状態受信 | 値に加えて`監視停止中 / Monitoring off` |
| Incompatible | 未対応schema受信 | 直前値を維持し、アプリ更新案内 |

「接続済み」はData Layerの到達可能nodeが確認できた場合だけ表示する。クラウド経由同期の可能性があるため、到達不能を「ペアリング解除」と断定せず「現在接続を確認できません」と表現する。

## 3. レイアウト

- Pixel Watch 4の41mmと45mmの円形画面に対応する。
- 主要操作は画面中央の安全領域へ置き、円周近くに小さいタップ領域を置かない。
- `ScalingLazyColumn`等のWear向けスクロールコンテナを使用し、フォント拡大時も下部操作へ到達可能にする。
- ambient/AOD中はWearアプリActivityを常時更新せず、システム管理のTile/コンプリケーションに委ねる。
- 色は情報の補助とし、残量値、充電アイコン、状態文言を常に併用する。

## 4. 色と表現

| 残量 | 推奨表現 | 注意 |
|---|---|---|
| しきい値超 | テーマのprimary | 正常を色だけで表さない |
| しきい値以下 | error + 警告アイコン | 通知済みかどうかとは別概念 |
| Stale | outline/amber系 + 時計アイコン | 数値を灰色化しすぎて読めなくしない |
| 充電中 | 稲妻アイコン + 文言 | 緑のみへ依存しない |

## 5. Tile

- 中央に`68%`、その下に`Phone`または`スマートフォン`を表示する。
- 充電中は稲妻アイコンを表示する。
- Stale時は`!`と最終同期の相対時間を表示する。
- タップ領域全体でWearメイン画面を開く。
- Tileに監視開始・権限要求など複雑な操作を置かない。
- Tile表示値はWear DataStoreのみから読み、Data Layerを同期ストレージとして直接読まない。

### コンプリケーション状態アイコン

- WFF v1～5の互換スロットへ、数値と`%`およびtint可能な単色アイコンを提供する。
- 充電中は`battery_charging_full`を最優先する。非充電かつ20%以下は`battery_alert`、それ以外は`battery_full`を使用する。
- 充電中の表示用title文字列は設定せず、アイコンと百分率だけを可視情報として提供する。content descriptionでは充電状態を維持する。
- 20%はコンプリケーションの固定表示境界であり、ユーザーの通知しきい値変更には追従しない。
- Staleでは状態別電池アイコンを維持して百分率へ`!`を付け、詳細をcontent descriptionへ置く。

## 6. 通知

- タイトル: `スマートフォンの電池残量が20%です` / `Phone battery is at 20%`。
- 本文: `設定値20%以下になりました。充電してください。` / `It reached your 20% threshold. Please charge your phone.`。
- タップ: Wearメイン画面。
- 同一eventIdの通知は1回だけ。
- 通知権限が拒否されている場合、次回Wearアプリ表示時に非強制の案内を表示する。
- 満充電通知タイトル: `スマートフォンの充電が完了しました` / `Phone is fully charged`。
- 満充電通知本文: `電池残量が100%になりました。` / `Battery level reached 100%.`。タップ、権限、期限、最大3回の投稿試行は低残量通知と同じ規則を適用する。

## 7. 更新と省電力

- DataItem受信時にローカル保存後、Tileとコンプリケーションへ更新要求を出す。
- 相対時刻の秒単位更新は行わない。分単位で十分とする。
- 画面非表示中にUI更新用タイマーを維持しない。
- Stale判定は保存値を書き換えず、表示時の現在時刻との差から算出する。

## 8. 受け入れ条件

- AC-004、AC-005、AC-008、AC-010、AC-011を満たす。
- 41mm、45mm、フォント最大設定で残量、Stale表示、再試行へ到達できる。
- TalkBackで残量、充電状態、鮮度、操作の順に意味が読み上げられる。

## 9. しきい値編集UI（BN-002提案）

- Wearメイン画面に現在の有効しきい値と「しきい値を変更」を表示する。
- 編集画面はWear固有の非セグメント型スライダーで5～100%を1%単位に変更でき、現在値、スライダー内の減少・増加、保存、戻るを円形画面の安全領域とスクロール内へ置く。Mobile Materialのスライダーで代用しない。
- スライダー内のタップ可能な減少・増加操作で1%ずつ下書きを変更し、主要操作のタップ領域、現在値、範囲、content descriptionを日英で提供する。リューズ回転はしきい値編集へ割り当てず、画面スクロールに使用する。
- 減少・増加操作はWear Proto DataStoreの下書きだけを更新する。連続操作中に変更要求を送信せず、明示的な保存操作で最終下書き値だけを1回送信する。
- 下書きはWear Proto DataStoreへ保存し、Activity再生成、Wear process再生成、端末再起動で失わない。
- 保存後は有効値を楽観的に書き換えず、次の状態を区別する。

| UI状態 | 表示・操作 |
|---|---|
| Editing | 下書き値、非セグメント型スライダー、1%刻みの減少・増加操作、保存操作を表示。調整中はMobileへ送信せず、リューズは画面スクロールに使用する |
| Sending | `Mobileへ確認中 / Checking with phone`。二重保存を無効化 |
| Applied, state pending | `保存しました。同期確認中 / Saved. Confirming sync` |
| Applied | Mobileのphone-state値を有効値として表示 |
| Disconnected / send failed | `まだ保存されていません / Not saved yet`、下書き維持、明示的な再試行 |
| Conflict | `Mobileで設定が変更されました / Setting changed on phone`、Mobile有効値、再編集 |
| Rejected / incompatible | 入力またはアプリ更新案内。有効値を変更しない |
| No Data | 編集保存を無効化し、Mobileの起動・接続・更新案内 |

- Stale状態から編集するときは「表示値が古い可能性」を編集画面にも残す。
- 未確定要求がある間は別の要求を作らず、同じ要求の再試行または破棄して現在のMobile値へ戻る操作だけを提供する。
- Tileとコンプリケーションには設定操作を追加しない。

## 10. 満充電通知設定UI（BN-004）

- W-001にMobileで確定済みのON/OFFを表示し、W-006で明示的に切り替える。切替操作は1件の要求を送るが、楽観的に確定表示しない。
- 後続phone-stateで確定値を更新する。期待値競合時はMobileが現在のphone-stateを再送するため、WearはMobile値を維持する。
- 切断/送信失敗では現在の確定表示を維持し、再接続だけでは送信しない。ユーザーが切替を再操作する。
- No Data、旧Mobile、対応Capabilityなしでは操作を無効化する。Stale時は古い値である警告を残し、競合し得ることを示す。
- 41mm/45mm、最大フォント、TalkBackで現在値とON/OFF操作へスクロール到達できるようにする。
