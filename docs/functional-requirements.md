# 機能要件仕様書

文書ID: FRS-001  
版: 0.1  
状態: Draft  
最終更新: 2026-07-20

## 1. 前提

- v1.0の監視対象はMobile端末の電池である。
- 電池残量は`0..100`の整数百分率へ正規化する。
- 初期しきい値は20%、設定可能範囲は5%から100%、刻みは1%とする。
- 通知は単なる「現在値が以下」ではなく「しきい値を上から下へ跨いだイベント」で発生させる。

## 2. 機能要件

### 2.1 初期設定と設定管理

| ID | 要件 |
|---|---|
| FR-001 | 初回起動時に機能説明、通知権限、継続監視の説明を順番に表示する |
| FR-002 | ユーザーはしきい値を5～100%の範囲で設定できる |
| FR-003 | ユーザーはバックグラウンド監視を明示的に開始・停止できる |
| FR-004 | 設定はMobileのProto DataStoreへ永続化し、再起動後も保持する |
| FR-005 | 不正な保存値は安全な既定値へ補正し、クラッシュしない |
| FR-006 | しきい値変更後、最新状態と設定をWearへ送る |

### 2.2 電池監視と判定

| ID | 要件 |
|---|---|
| FR-010 | 監視中は`ACTION_BATTERY_CHANGED`をコンテキスト登録したReceiverで受信する |
| FR-011 | `level`と`scale`から`floor(level * 100 / scale)`を算出し、0～100に制限する |
| FR-012 | `previousLevel > threshold && currentLevel <= threshold`で到達イベントを生成する |
| FR-013 | 初回観測時にすでにしきい値以下でも、監視開始の直後に1回だけ状態通知するかを設定で制御する。v1.0既定値は通知しない |
| FR-014 | 同一放電サイクルでは同じしきい値イベントを1回だけ通知する |
| FR-015 | 残量が`threshold + 2`以上へ戻る、または充電開始後にしきい値を上回った場合に再アームする |
| FR-016 | 充電中も状態同期は継続するが、新しい低残量通知は生成しない |
| FR-017 | 監視停止中はしきい値イベントを生成せず、Wearには監視停止状態を同期する |
| FR-018 | 端末時刻変更に影響されない順序判定用に単調増加`sequence`を使用する |

### 2.3 Mobile通知

| ID | 要件 |
|---|---|
| FR-020 | 通知許可がある場合、到達イベントごとにMobileへ1件通知する |
| FR-021 | 通知には現在残量、設定しきい値、充電を促す文言、設定画面を開くアクションを含める |
| FR-022 | 通知許可がない場合もイベントを保存・同期し、画面に権限不足を表示する |
| FR-023 | 継続監視中は停止アクション付きの低重要度ongoing通知を表示する |
| FR-024 | 通知のIDはイベントIDから決定的に生成し、再処理で重複しない |

### 2.4 Wear状態表示

| ID | 要件 |
|---|---|
| FR-030 | WearアプリにMobile電池残量、充電状態、しきい値、最終更新時刻を表示する |
| FR-031 | 受信時刻から2分以内をFresh、2分超5分以内をDelayed、5分超をStaleと表示する |
| FR-032 | Stale時は値を消さず、値に「古い可能性」と最終更新時刻を併記する |
| FR-033 | 一度も受信していない場合は未接続案内と再試行操作を表示する |
| FR-034 | Tileにも残量、鮮度、充電状態を表示し、タップでWearアプリを開く |

### 2.5 Wear通知

| ID | 要件 |
|---|---|
| FR-040 | 有効期限内の未処理到達イベントを受信した場合、Wearにローカル通知する |
| FR-041 | 同一`eventId`をWear DataStoreへ記録し、再受信時は通知しない |
| FR-042 | 受信時点でイベントの`expiresAt`を過ぎている場合は通知せず、状態のみ更新する |
| FR-043 | Wear通知権限がない場合、アプリ内に許可案内を表示する |

### 2.6 コンプリケーション

| ID | 要件 |
|---|---|
| FR-050 | `RANGED_VALUE`と`SHORT_TEXT`のコンプリケーションデータを提供する |
| FR-051 | Fresh時は百分率と充電状態、Stale時は警告表現を返す |
| FR-052 | データ未受信時は`NoDataComplicationData`とプレースホルダーを返す |
| FR-053 | 状態受信後にアクティブなコンプリケーションの更新を要求する |
| FR-054 | コンプリケーションのタップでWearメイン画面を開く |

### 2.7 同期と復旧

| ID | 要件 |
|---|---|
| FR-060 | Mobileは固定DataItemパスへ最新状態を書き込む |
| FR-061 | 状態更新には`schemaVersion`、`sequence`、取得時刻を含める |
| FR-062 | Wearは順序キーが保存済み以下の状態を破棄する |
| FR-063 | 切断中もMobileは最新DataItemを更新し、再接続後に最新状態へ収束させる |
| FR-064 | 接続・再接続時にMobileは現在値を再取得してurgent送信する |
| FR-065 | schemaVersion、不正型、範囲外、必須項目欠落を検証し、異常データを保存・表示・通知に使用しない |
| FR-066 | 互換性のない新しいschemaVersionを受信した場合は診断状態へ記録し、クラッシュしない |

### 2.8 多言語・アクセシビリティ

| ID | 要件 |
|---|---|
| FR-070 | OSのアプリ言語が日本語なら日本語、それ以外は英語を既定表示する |
| FR-071 | 画面、通知、Tile、コンプリケーション説明、権限説明を日英で提供する |
| FR-072 | 文字列をKotlinへ直書きしない |
| FR-073 | 残量状態を色だけで表現せず、数値・アイコン・文言を併用する |

## 3. 非機能要件

| ID | 要件 |
|---|---|
| NFR-010 | Mobile/Wearのdomain層はAndroidフレームワークに依存せずJVM単体テスト可能とする |
| NFR-011 | 電池イベント処理は冪等であり、同じ入力を複数回処理しても結果を重複させない |
| NFR-012 | 個人データ、広告ID、位置情報、アカウント情報を収集しない |
| NFR-013 | 外部分析SDKをv1.0へ導入しない |
| NFR-014 | Data Layer payloadは1KB程度を目標とし、100KB上限へ近づけない |
| NFR-015 | ログに端末識別子を出力せず、イベントIDはランダムUUIDを使用する |
| NFR-016 | 折りたたみ・展開中のActivity再生成やウィンドウサイズ変更で設定入力を失わない |
| NFR-017 | Wearの41mm/45mm、フォント拡大で主要情報と操作が欠けない |

## 4. 受け入れ条件

| ID | 対応要件 | Given / When / Then |
|---|---|---|
| AC-001 | FR-002, FR-004 | しきい値20%を15%へ変更してMobileを再起動すると、15%が表示される |
| AC-002 | FR-012, FR-014 | 21→20→19%と変化したとき、20%で各端末最大1回だけ通知される |
| AC-003 | FR-015 | 通知後に22%以上へ回復し、再び20%以下へ下がると新しい通知が1回発生する |
| AC-004 | FR-030, FR-031 | 接続中にMobileが更新されると、Wearへ残量と取得時刻が反映される |
| AC-005 | FR-032 | 最終同期から5分経過すると、Wearアプリ・Tile・コンプリケーションがStaleを示す |
| AC-006 | FR-063, FR-064 | 切断中に複数回更新して再接続すると、中間値ではなく最新値へ収束する |
| AC-007 | FR-041, FR-042 | 同じイベント再送または期限切れイベント受信で、Wear通知が重複・遅延発火しない |
| AC-008 | FR-065 | 残量101、負値、必須項目欠落を受信してもクラッシュせず直前の正常値を保持する |
| AC-009 | PR-007 | Pixel 10 Pro Foldを通知設定画面のまま折りたたみ・展開しても入力と監視状態を保持する |
| AC-010 | PR-008 | Pixel Watch 4の41mm/45mmで画面、Tile、通知、コンプリケーションが操作可能である |
| AC-011 | FR-070, FR-071 | アプリ言語を日英で切り替えると、再起動なしまたはOS標準挙動で全文言語が切り替わる |
| AC-012 | FR-003, FR-023 | ongoing通知の停止操作を押すと監視が止まり、Watchへ停止状態が反映される |
